# 存储网络交易

食物按件交易，品质和热量共同决定基础单价：品质 0 的起价为 ¥28，每提高一级乘 1.75；热量越多，在该品质档位内的加价越高，加价最高趋近 50%，保证热量不能反转相邻品质档位。热量加价公式为 `1 + 0.5 × E / (E + 2)`，E 使用游戏原生 CaloriesPerUnit / 1000000，最后保留两位小数。无可食用品质的烹饪原料基础价为 ¥8。实际买卖报价仍叠加行情、商人风格和好感优惠，因此不同时间或不同商人的最终报价可能交叉。

搜索框右侧的“周报”打开星际商讯，从上次实际刊发时刻起满 7 个游戏周期才刊发下一期（例如第 7.7 周期刊发后，要到第 14.7 周期才更新），保存最近 16 期并标记未读。航运电台预告下一位实际到访的商人；柜台侧写、货单消息与码头茶话提供性格、习惯及经营方面的线索，需要对照商人身份卡和实际货单判断。报价是刊发时的记录，不能当作未来交易承诺。周报、已读状态与到访预告随存档保存，打开窗口或读档不会重抽；长时间跳过仅生成当期消息，不补造往期见闻。中文源文本和英文 PO 翻译均已提供。

每期以 8 则为目标，从到访预告、商人侧写、柜台轶事、货单线索、同货比价、价签追踪、离港时间、往来消息、柜台索引、收购余款和新来商人中轮换选稿。同一栏目每期最多一则，优先选择近期未报道的商人和商品。同一艘船的到访预告与同一趟离港消息在保留的报纸中只刊登一次；普通话题优先冷却 3 期，消息不足时缩短到 1 期，相同原文仍在最近 3 期内禁用。实在没有足够的新消息时减少条数，不补造行情。

同货比价、价签追踪和收购余款来自实际状态；变化不足 2% 的价签不作为涨跌新闻。正文有多个中英文写法并避开最近两期使用过的版本，商人侧写另有 8 类独立叙事。报道的话题、人物、栏目和写法随存档保存；打开报纸和读档不会重选内容。旧期保持原来的选稿，后续新刊使用去重和栏目轮换。

供应商卡片右侧偶尔出现橙色感叹号，点击阅读这位商人的口信。每批消息从实际发出时刻起满 7 周期才更新，最多两位商人可提供航路消息、手边货物与闲谈；阅读后消失，窗口结束或商人离站时过期。特殊商人有各自的隐晦口风，不直接揭露隐藏身份。消息与已读状态随存档保存，刷新不会重抽；它与原有底部对话事件按钮各自独立，不需要配置 AI。

需要同时启用独立的 StorageNetworkTrading 与前置 StorageNetwork。在存储网络顶部“订单”右侧点击“交易”。使用当前星球的在线网络仓库卖出材料赚取货币，再买入材料、食物、种子或装备。材料按 kg、物品按件交易；初始余额为零。点击“买入”或“卖出”打开与转移数量窗口相同风格的弹窗，拖动滑块或直接输入数量，也可选择“全部”。预览数量、单价、总额、交付位置及成交后的余额，再点击“确认成交”；取消或关闭不会成交。

- 同时有 5 位供货商，默认各自停留 1～30 周期，到期自动补位。每增加20点好感，下次到访的随机下限提高1周期，最多变为5～30周期；本次离站时间不变。进度条按各自本次总停留时间显示剩余比例。
- 供应商卡片左侧是由游戏复制人脸型、头发、眼睛和嘴型部件拼接的头像，右侧为固定姓名和经营类别，底部进度条表示剩余停留时间。头像使用原生复制人表格的 UI 动画部件，不会生成殖民地中的实际复制人。姓名和各部件资源 ID 随供应商保存，交易弹窗和成交记录使用同一姓名，可供后续对话系统复用。收购、供货额度和供货风格可在悬停提示中查看，当前供应商额度也显示在交易底部。
- 按游戏 Tag 划分食物、金属、矿物、种子、装备、液体、气体和工业材料商。每位供货商独立随机选择类别，首批也不固定；同场可以出现3位金属商，甚至5位同类商。相同类别的供货商独立生成货单、库存、报价和交易额度。DLC 模式下已有供货商停留结束后离港，新的商人按航行时间到访，每个星球最多停留五位，不再立即补位；无 DLC 时保留旧补位机制。
- 普通供货商随机提供其类别中最多 12 种商品，固定角色最多 6 种；只收购和出售专营类别的货物。玩家卖出同类货物后进入其库存。商品行显示游戏原生图标及颜色。
- 货物列表合并供应商现货和网络可售材料，同一行同时显示买入、卖出报价与按钮，不用切换买卖页面。两边都没有库存的商品不显示，无货可买或没有材料可卖的按钮禁用。成交记录常驻右侧，不需要单独切页。
- 商品名称、网络库存、供货库存和价格分层显示；成交记录使用图标卡片，收入为绿色、支出为红色，数量、余额和时间用不同文字色区分。
- 每周期更新报价：长期趋势叠加短线涨跌、每日消息与偶发供需冲击，商人的供货和收购还各有独立波动。短线可能连续上涨或突然回落，冲击会在数周期内增强和消退；同周期反复打开界面不会重抽价格。商品行显示较上周期的涨跌，红色表示上涨、绿色表示下跌、灰色表示持平。可利用周期和供应商更替带来的价格变化倒货；同一供货商的买入价高于卖出价。
- 商品名称旁的“走势”打开每周期报价折线图。“本供应商”显示本次停留的买入红线、卖出绿线；“市场近30周期”和“市场近60周期”显示跨供应商的市场参考价与期间高低价。市场参考价没有供应商加价和买卖差价，不是可成交报价。鼠标移入图表可查看对应周期的具体价格和涨跌。
- 行情从功能启用后开始记录，每周期保存最新报价，最多保留60周期的市场数据。成交导致当前报价变化时只更新当前点，不改变过去周期的价格，也不补造缺失周期。行情随存档保存。
- 顶部筛选依次切换全部、可买、可卖。可买与可卖筛选同时考虑余额、供应商额度及接收容量。数量弹窗记住该商品上次成功买入或卖出的数量，两种方向分别保存。
- 大宗采购商库存更多且收购价差较小，折扣供货商销售加价较低并偏重常见货物，精品供货商偏重高价值商品、货量更少且销售加价较高。分类基础价格区分原矿、精炼材料、稀有材料及装备；食品依据热量和品质定价。这些是模组自定的平衡参数。
- 每位供货商每次停留的买入和卖出基准额度分别为随机 20,000～80,000，好感提升可额外解锁额度，交易会显示各自剩余额度。
- 供应商每周期补回初始库存的10%，整件货物至少补1件，只补其初始货单，补到初始数量为止。玩家卖出的额外库存不会被重复补货；逐周期补货不会恢复本次停留的金额额度。
- 丰收、建设潮、工业清仓、运输紧张、播种季和矿物增产按商品类别影响价格，事件影响逐步增强和减弱。每周期读取当前世界资源快照，库存越多，对应市场价格越低；库存影响最多压低6%，每周期最多变动0.5个百分点。已记录的交易库存增减会从行情信号中扣除，不将玩家倒货作为全市场涨跌信号；成交仍会改变该商人的库存与剩余额度，影响其自身报价。
- 供应商按类型偏好精炼金属、金属矿石、熟食、原料或高价值货物，符合偏好的收购报价加价3%。鼠标移入供应商按钮或卖出按钮可查看偏好。同一供应商的买卖差价覆盖供需影响，反复即买即卖不会增加货币；不同供应商的报价差异可以用于倒货，仍受库存、余额和各自额度限制。
- 交易数量会按库存、货币、额度和目标仓库容量截取，反馈实际成交数量及金额。
- 报价面板在成交前显示可成交上限及限制说明，并可一键填入最大数量。确认时重新检查周期、供应商、单价和可成交量，发生变化时要求玩家重新检查；记录只在实际成交后产生。
- 购买可以分配到多个符合过滤器的网络仓库，报价预先检查可接收容量。成交记录保存最近 64 笔，包括成交周期、方向、货物、数量、单价、总额、供应商、星球和成交后余额。
- 购买使用网络仓库过滤器；网络掉线或无合适仓库时无法购买。生产订单预留材料不计入可售数量。
- 数量弹窗预览各接收仓库的数量；无合适目标时区分服务器类型、离线、满仓及过滤器限制，并提供仓库定位。定位按钮可逐个查看目标。成交记录保存实际交付位置和建筑身份，读档后仍可定位尚存在的仓库。
- 转移期间阻止重复交易与市场刷新，货物先激活再入库。结算核对仓库实际增减量；若同步仓库监听器中断转移，已交付部分按确认的报价结算并明确反馈部分成交，未入库的新货物会清理，避免免费掉落。
- 余额、供应商身份、离开时间、库存和双方累计成交金额随游戏存档保存。关闭面板和读档不会刷新额度。
- 旧存档中的混合供货商会一次性转换为专营供货商并重建对应类别货单，保留余额、累计成交金额、额度及离开时间。

## 角色对话与 AI 群聊

供应商具有公开身份、性格、关系记忆和本地对话选项，固定角色的关系记忆可跨到访保留。实际成交会增加好感，好感可影响报价、解锁额度及后续到访的最短停留时间。

在交易页的 AI 设置中填写服务名称、Chat Completions 兼容接口地址、模型与 API Key，并设置群聊回复概率（默认 30%）。配置保存在当前 `.sav` 旁的 `<存档文件名>.sav.StorageNetworkTradingAi.json`，另存与自动保存时会生成对应配置；API Key 使用当前 Windows 账户的 DPAPI 加密，换账户或电脑后可能需要重新填写。未配置可用服务时，群聊会提示配置要求，普通交易与本地选项对话仍可使用。

点击群聊按钮发送消息，可用 `@姓名#到访编号` 指定商人，也支持部分姓名称呼与追问识别；识别规则有限，重名时需明确到访编号。群聊窗口支持拖动，记录随市场状态保存。请求会将角色背景、交易快照与相关聊天记录发送给配置的服务；AI 只生成台词，不执行买卖或赠送。配置和实现细节见 [AI 接入说明](./AI_DIALOGUE.md)。

## 验证

运行 `StorageNetwork.Tests/Verify.ps1` 可执行编译、交易经济规则测试、真实游戏程序集 JSON 保存检查以及其他现有检查。

验证涵盖中英文 PO、公开 API 兼容性与依赖边界、AI 配置加密及存档旁文件、Harmony 目标与静态性能规则；详见 [验证说明](../../StorageNetwork.Tests/README.md)。AI 服务连通性、真实聊天表现及窗口交互仍需游戏内实测。

游戏内验收：卖出 100 kg 铁，检查材料减少且余额增加；买入材料及一件装备，检查网络库存增加；在余额、库存或额度不足时再次交易，检查实际数量及余额；保存并读档，检查余额和额度；关闭面板推进到供应商离开，重新打开检查替补供应商；断电或关闭仓库过滤器，检查购买被阻止；用关闭按钮、Escape 或右键单击逐层关闭界面，确认右键拖动不会触发关闭。

成交流程验收：在同一张货物列表点击“买入”，输入数量并核对总价及余额，再确认；直接点击同一行“卖出”重复卖出操作，检查所得货币与右侧记录一致；在报价后跨周期或修改网络库存，检查确认时提示重新检查；将网络剩余容量分散在两个仓库，检查最大数量及交付；保存读档后检查最近成交记录及供货商额度仍保留。

界面刷新验收：列表滚动到中间后连续买卖或等待报价变化，确认滚动位置保持、商品文字不越出行或滚动区；切换供应商、翻页及搜索后检查货物、图标和交易对象一致。商品行使用与主面板一致的缓存刷新，数量和价格变化只更新已有文字，列表结构变化才安排一次合并布局。

新增功能验收：连续两次买入同一商品，检查记住的数量与需求变化；将买入数量分散到两个仓库，核对预览、实际库存、扣款和记录，使用定位按钮查看目标；推进一周期，检查补货增加、金额额度不恢复、过去行情点不改变；切换供应商后检查市场参考价仍连续积累。交易异常的仓库事件需要游戏内集成验证，独立测试无法运行 Unity 组件生命周期。
