# 存储网络算法优化与验收记录

日期：2026-10-13。分支：`codex/storage-network-algorithm-optimization`。

## 实现结果

- 已知搬运按变化标签更新仓库与世界汇总，以更新前后的实际差值处理阈值残量；无关来源桶保持排序缓存。联网、归属、容量资格或未知事件变化仍走原生刷新。
- 严格查询按单仓库、世界及停靠火箭集合刷新脏数据；全网络查询和外层搬运事务的起始基线仍全局同步。迁移同步更新旧、新世界的记录归属与脏集合。
- 数量汇总、元素质量有效状态、物品/食物/显示明细分开维护。搬运元数据没有可靠的原生元素 hash 与物品阈值变化信息，元素量采用单独的按需原生扫描；不推断温度、病菌或食物属性。
- 农业快照按种子保存稀疏累计量，以二分查询先前端口预留。端口序号保留原优先级及重复 ID 的最后覆盖语义；缺失端口仍返回零。筛选字典不再复制，物品工作区租借后通过 `finally` 归还，保留池大小与容量有限制。
- 订单中心侧栏保留半秒检查，文字、提示、按钮及进度值变化才写入；重新启用、切换目标、语言变化强制同步。启用事件通过 `OnCmpEnable` 调用引擎基类。
- 订单与跟踪结构的布局请求合并为一次根布局处理，原生 Canvas 调度继续处理当帧布局。DIY 材料标签在选择变化时构造，包括修改已有节点的选择；全局条件字段在求值前检测变化。
- 新增扫描条目、整仓/明细刷新、标签更新、来源桶排序、农业累计条目、侧栏实时文字网格重建计数。计数只在现有性能采样启用时累积；保留现有 CPU、分配和 GC 记录。
- 测试目录已纳入版本管理。公共 API、序列化字段和用户配置保持原样。

### 保留的原有静态检查失败

改动前另外三项源码检查失败：订单同步布局、DIY 标签构造、跟踪绑定方法定位。前两项已优化；跟踪方法本身已是实例方法，检查已修正为检查实际实例方法体。

先用 `PrepareBenchmarkFixture.ps1` 在游戏关闭时准备副本。每次采样结束，将该次日志另存，并通过 `AnalyzeFrameProfile.ps1 -LogPath <日志> -OutputJson <报告>` 导出。主面板/分类场景按 README 增加对应必需区域和布局限制参数。比较工具要求三份独立基线报告、三份独立候选报告、相同的活动端口数和面板要求。

```powershell
& .\StorageNetwork.Tests\CompareFrameProfiles.ps1 `
  -BaselineReports @('before1.json', 'before2.json', 'before3.json') `
  -CandidateReports @('after1.json', 'after2.json', 'after3.json') `
  -PrimaryScenario -OutputJson comparison.json
```

导出报告包含绝对门限是否通过、失败原因和会话错误数；超过绝对耗时门限仍导出测量数据，但保留失败状态。会话有模组错误或影子不一致时，比较工具拒绝采用。

比较使用各次运行窗口中位数，再取三次运行的中位数。主压力场景要求 P95 至少降低 15%，其他场景允许至多 5% 的 P95/P99 回退；CPU 接近采样精度时扩大采样并结合操作量。分配跟踪不受运行环境支持时保持缺失状态，不记作零。工具仅验证报告内可检查的指标，存档、速度、镜头等条件仍需与运行记录核对。

## 2026-10-15：搬运范围与事务内来源查询

本轮保留全部功能、搬运数量、更新周期、来源排序规则、过滤规则以及存档/API 格式。

### 改动

- 网络搬运的九个事务入口均明确传入世界或端点范围。普通网络搬运只同步本世界及其可访问世界的脏库存；停靠火箭仍包含在范围内，中继在线时仍同步完整可访问网络。指定仓库之间的直接搬运只同步两个端点。
- 如果显式目标或嵌套搬运触及范围外已有脏数据的仓库，该端点在整个事务期间保持原生读取与提交刷新，防止把已包含搬运结果的原生数量再次叠加差值。非服务器端口不会因此触发服务器整仓刷新。
- 事务内来源查询使用已提交的材料来源桶与本次触及仓库的并集，保留新增匹配来源及未知变动的原生回退。候选以原有的最大匹配数量、稳定 ID 规则排序，保留排除列表与重复标签语义。
- 每个世界先估计来源桶规模；材料类别覆盖至少一半仓库时保留直接遍历，避免广泛分类查询构造同样规模的候选字典。稀疏世界与稠密世界可以混合查询。
- 性能日志增加 `pendingSourceChecks`，现有解析器直接导出该字段，新增合成日志测试确保不会丢失。计数仅在采样启用时累积。

### 验证与边界

- Release 编译通过。确定性运行时与源码检查共 4,637 项断言通过。
- 新增 1,003 本地服务器压力场景：查询一种材料的事务内来源候选检查为 3 次，而原实现遍历 1,003 个本地服务器。广泛分类场景覆盖本地与停靠火箭共 1,004 个服务器，每个服务器只检查一次。
- 新增 120 组固定种子的动态场景：跨世界搬运、预先脏数据、未知变动、停靠变化、中继开关、排除列表、重复标签；来源完整顺序与直接读取原生库存的全扫描参考结果逐项一致。
- 另覆盖同世界无关脏仓库、端点直接搬运、范围外显式目标、嵌套事务、非索引端口、旧版诊断模式；保留既有 1,000 次连续搬运与质量/温度/食品等验证。
